Un projet, un environnement

La cheatsheet complète. Chaque commande a un bouton Essayer qui la place dans le simulateur, et un bouton Copier pour ton vrai terminal.

  1. base reste videIl sert uniquement à faire tourner conda. On n'y installe jamais rien.
  2. Un projet = un envCréé avant d'écrire la première ligne de code.
  3. La recette vit dans le projetenvironment.yml, ou pyproject.toml + uv.lock.
  4. Regarde le promptAvant d'installer, le prompt doit afficher (nom-du-projet), ni (base) ni rien.
  5. Projet fini, env suppriméLa recette suffit pour le recréer.

conda gère aussi ce qui n'est pas du Python (Java pour Spark, librairies C). uv est beaucoup plus rapide et range tout dans le dossier du projet.

Nouveau projet avec conda

# 1. Créer l'env (toujours préciser Python)
conda create -n mon_projet python=3.12 -y
conda activate mon_projet
# 2. Installer ce dont j'ai besoin (+ ipykernel pour les notebooks)
conda install pandas scikit-learn plotly ipykernel -y
# 3. Rendre l'env visible dans Jupyter / VS Code
python -m ipykernel install --user --name mon_projet --display-name "Python (mon_projet)"
# 4. Sauvegarder la recette dans le dossier du projet
conda env export --from-history | grep -v "^prefix" > environment.yml
# Recréer l'env ailleurs, ou après l'avoir supprimé
conda env create -f environment.yml

Un paquet absent de conda-forge ? python -m pip install nom, mais seulement dans l'env actif du projet et après les paquets conda.

Nouveau projet avec uv

# Dans un dossier dédié, jamais directement dans ~
mkdir mon_app && cd mon_app
uv init --python 3.13
uv add fastapi requests
uv run python main.py
# Projet récupéré : recrée .venv depuis uv.lock
uv sync
# Dépendance de développement
uv add --dev pytest
# Outil global isolé (comme obsidian-rag)
uv tool install --editable .

Si un env conda est actif, fais d'abord conda deactivate : sinon uv peut construire le .venv avec le Python de conda. --managed-python force uv à utiliser son propre Python. Ajoute .venv/ au .gitignore.

Jupyter et VS Code

En haut à droite du notebook, Select Kernel, puis choisis Python (mon_projet) ou le .venv du projet. Si l'env n'apparaît pas, c'est qu'ipykernel n'y est pas installé.

jupyter kernelspec list
jupyter kernelspec uninstall mon_projet -y

jupyter n'existe que dans un env qui contient ipykernel. Supprime le kernel avant l'env, tant qu'il est encore actif.

Ménage, une fois par trimestre

# Un env sans projet actif ? On le supprime
conda env list
conda env remove -n vieux_projet -y
# Caches
conda clean --all -y
python3 -m pip cache purge
uv cache prune

Signaux d'alerte

  • Je tape pip install alors que le prompt affiche (base) ou rien : stop, j'active d'abord l'env du projet.
  • zsh: command not found: pip ou python : c'est normal, aucun env n'est actif. C'est le garde-fou, pas une panne.
  • Un notebook tourne sur le kernel générique « Python 3 » : je choisis le kernel du projet.
  • Je copie un !pip install trouvé sur internet dans un notebook : je l'installe plutôt dans l'env, puis je mets à jour environment.yml.
